## 3. Problèmes Identifiés

### 3.1 Système CSS dual

| Pattern | Composants | Impact |
|---------|-----------|--------|
| Scoped `<style>` uniquement | 29 (52%) | ✅ Bon — encapsulation Astro native |
| Tailwind utilities uniquement | 27 (48%) | ⚠️ Audit nécessaire — classes longues |
| Hybride (scoped + Tailwind) | 5-6 | ❌ Incohérent — deux langages |

### 3.2 Valeurs arbitraires Tailwind

```astro
<!-- Exemple Input.astro — 15+ classes utilitaires -->
class="w-full px-3 p-2 bg-[var(--color-surface-2)] border border-[var(--color-border)] rounded-[var(--radius-sm)] text-[var(--color-text)] ..."
```

**80+ instances** de `text-[1.3rem]`, `gap-[1.2rem]`, `bg-[var(--color-surface-2)]` qui ré-implémentent des variables CSS dans la syntaxe Tailwind. Bruit inutile.

### 3.3 Duplications

| Duplication | Lieux | Count |
|-------------|-------|-------|
| `@media (prefers-reduced-motion)` | globals.css (x2), button.css, AppShell, Header, Sidebar, Card, Dialog | 7+ |
| Types NavLeaf/NavItem/NavGroup | AppLayout.astro, AppShell.astro | 2 |
| Grid responsive | globals.css + pages individuelles | 4+ |
| `setLocale` + `const L = t()` | 21 pages | 21 |

### 3.4 Fichiers volumineux

| Fichier | Lignes | Problème |
|---------|--------|----------|
| `index.astro` | 1628 | Template + script + style mélangés |
| `AppShell.astro` | 857 | Drawer markup duplicé avec Sidebar |
| `Sidebar.astro` | 663 | Styles nav + drawer presque identiques |
| `globals.css` | 391 | Reset + tokens + utilities + composants mélangés |

### 3.5 Styles globaux polluants

- `Table.astro` utilise `<style is:global>` → impacte tous les `<th>` dans `[data-ui-table]`
- `globals.css` contient `.type-pill`, `.tone--*`, `.set-row-grid` qui ne sont pas des utilities

### 3.6 input-stepper.css dans public/

Fichier CSS dans `public/` — pas traité par le build pipeline, ne peut pas utiliser les tokens du design system.

### 4.2 Conventions

- **Fichiers composants**: PascalCase (`Button.astro`)
- **Fichiers styles**: kebab-case (`button.css`)
- **CSS components**: BEM — `.block__element--modifier`
- **Variables CSS**: Tokens centralisés, jamais de valeurs hardcodées
- **Props**: TypeScript interface avec defaults, `class?: string` pour passthrough
- **Imports**: Frontmatter uniquement, pas de `<link>` dans templates

## 5. Stratégie CSS

### 5.1 Tokens (`tokens.css`)

Déjà solide. Garder tel quel. Quand Tailwind sera retiré :
- Supprimer `@import "tailwindcss"` et le bloc `@theme`
- Convertir en `:root` CSS variables classiques

### 5.2 Reset (`reset.css`)

Extraire le bloc `@layer base` de `globals.css` (lignes 10-209) dans un fichier dédié.

### 5.3 Global (`global.css`)

Garder uniquement les règles réellement globales :
- `body`, `html`, typographie de base
- `a`, `button`, `ul/ol`, `img/svg`
- `:focus-visible`, `::selection`
- Scrollbar
- `[x-cloak]` (Alpine)
- `prefers-reduced-motion` (une seule fois)

### 5.4 Utilities (`utilities.css`)

Déplacer les classes partagées de `globals.css` :
- `.type-pill` + variants
- `.tone--*` (warmup, work, top, drop, failure, easy, moderate, hard, max)
- `.text-label`, `.text-body-secondary`, `.text-caption`, `.text-settings-label`, `.text-stat-value`
- `.text-display`
- `.dt-label`
- `.set-row-grid`
- `.card-surface`
- `.grid-responsive-2`, `.grid-responsive-3`
- `.anim-fade-in`
- `.section-gap`
- `.border-b-separator`

### 5.5 Composants

Chaque composant garde son `<style>` scoped (Astro gère l'encapsulation).

**Pour les 27 composants Tailwind-only**: les convertir progressivement en scoped CSS en utilisant les tokens existants. Priorité :
1. Composants simples (Icon, Avatar, EmptyState)
2. Composants moyens (Input, FormField, Card)
3. Composants complexes (Dialog, Table, Toast)

## 7. Checklist de Sécurité

Avant de modifier chaque fichier :

1. Vérifier les imports (qui importe ce fichier)
2. Vérifier où le composant est utilisé (toutes les pages)
3. Vérifier les dépendances Alpine (x-data, x-show, x-for)
4. Vérifier les styles hérités (scoped vs global)
5. Vérifier les effets de bord (scripts, event listeners)

**Règles** :
- Ne supprimer aucun fichier sans confirmer zéro référence
- Ne casser aucune route existante
- Ne pas changer les fonctionnalités
- `pnpm run check` après chaque modification
- `pnpm run build` pour valider

---

## 8. Performance

Respecter les principes Astro :
- Rendu statique privilégié
- Pas de JS client inutile
- `client:*` minimal (l'app utilise Alpine.js, pas React)
- Imports optimisés
- Pas d'abstractions inutiles
- Tree-shaking préservé
